# Свойства объектов на карте

Шаблон в библиотеке определяет общие значения. Размещение хранит ссылку на него
и только отличающиеся свойства в `overrides`. Это позволяет обойтись пятью
материалами дверей вместо десятков сочетаний замков, состояний и прочности.

1. Поставьте объект из его собственного раздела палитры «Объекты».
2. Нажмите **V** («Выделение») и выберите его на карте.
3. Во вкладке **«Клетка» → «Свойства экземпляра»** настройте нужные поля.
   Если в клетке несколько объектов, выберите нужную карточку под инспектором.
4. Сохраните карту **Ctrl+S** и запустите тест.

Дверь показывает основные параметры сразу. У остальных объектов поля
раскрываются отдельно: название, описание, внешний вид и механика.
Пометка «изменено» обозначает локальное значение. «Вернуть из шаблона»
сбрасывает поле, «Сбросить настройки экземпляра» — все настройки объекта.
Ненастроенные поля наследуют последующие изменения шаблона.

| Объект | Доступные настройки |
| --- | --- |
| Дверь | Материал, состояние, запирание, качество и сложность замка, максимальные HP |
| Ловушка | Скрытость, характеристика, СЛ, повторяемость, последствия успеха и провала |
| Точка интереса | Название, описание, символ, цвета, ссылка на испытание |
| Испытание точки интереса | Текст, варианты, требования и теги, проверки, время, последствия |
| Предмет | Вес, тип, теги, прочность, применения, слоты, урон, свет, свойства и помощь в проверках |
| Существо | HP, КД, характеристики, скорость, инициатива, инвентарь, магия и особые действия |
| Рисунок | Свойства графического документа |

Источники света сохраняют собственные параметры радиусов и включения;
проход и обзор обычных клеток задаются отдельными масками карты.
Настройки используют те же формы и реестр механик, что библиотека.
Новая механика с зарегистрированной схемой появляется в редакторах эффектов.

Пример двух независимых дверей из одного шаблона:

```json
"doors": [
  {"id": "entrance", "ref": "base:door_wood", "x": 3, "y": 4},
  {"id": "vault", "ref": "base:door_wood", "x": 8, "y": 4,
   "overrides": {"brush": {"door": {
     "locked": true, "lock_quality": "expensive", "lock_complexity": "complex"
   }}}}
]
```

Объекты объединяются рекурсивно, списки заменяются целиком, `null` явно
сбрасывает допускающее его поле. `id` и `schema_version` шаблона фиксированы.
Поля и значения проверяются общей строгой схемой после объединения;
проверяются ссылки и зависимости пакетов, эффекты, допустимость старта героя.
У точки интереса отдельное поле `challenge_overrides` настраивает связанное
испытание без изменения других точек с тем же испытанием.

Undo/redo и копирование области сохраняют настройки вместе с размещениями.
Оконная игра и терминал собирают экземпляры через общую фабрику. Игровые
изменения HP, ресурсов и срабатываний хранятся отдельно от авторских данных;
перезапуск теста возвращает исходные настройки. Подобранные предметы сохраняют
свои локальные свойства, в том числе при переходе на другую карту и сохранении.

Без локальных настроек движок использует общие неизменяемые определения.
Настроенные определения собираются при создании уровня, а не на каждом ходе.

Внешние варианты одного шаблона выбираются через «Вариант внешнего вида».
Поле `storage` настраивает вместимость, начальное содержимое и личный режим
конкретного контейнера. [Обмен и формат контейнеров](storage.md).
Мебель и двери хранятся в `objects/`; предметам, ловушкам и точкам интереса
дополнительные тайлы не нужны. [Результаты ревизии](content-revision.md).
