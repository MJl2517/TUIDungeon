# Пакеты и формат документов

[Дверные объекты и размещения `doors`](doors.md) описывают динамические преграды,
замки и их состояния. Параметры двери находятся в `brush.door` объекта окружения.

[Общие замки и служебные индикаторы](locks.md): `storage.lock` у контейнеров,
качество и механизм замка, теги `lock_indicator`, `lock_simple`, `lock_complex`.

[Типы урона и защита](damage.md): `damage_type` у оружия, атак и эффектов;
`damage_profile` у монстров, рас, классов и защитного снаряжения.

Рабочий контент находится в `packs/`. Источник проверки и JSON Schema —
`tuidungeon/content/schemas.py`; перечисление `MODELS` связывает категории с
моделями. Схемы строгие: лишние поля, неверные типы, ширина символа, размеры,
кубики и ссылки отклоняются до сохранения.

[Библиотека символов и формат масок 16×16](symbols.md): поле `symbol` ссылается
на `symbols/`, `state_symbols` задаёт вид состояний двери. `glyph`/`char`
сохраняются для чтения прежних документов; новые изображения выбираются из библиотеки.

## Манифест и ссылки

```text
packs/my_pack/
  manifest.json
  symbols/ art/ tiles/ objects/ maps/ monsters/ equipment/ spells/ actions/
  classes/ races/ backgrounds/ challenges/ traps/ points_of_interest/
```

```json
{
  "schema_version": 1,
  "id": "my_pack",
  "name": "Мои подземелья",
  "version": "1.0.0",
  "dependencies": ["base"]
}
```

ID — строчные латинские буквы, цифры и `_`, первый символ — буква.
ID пакета совпадает с папкой. Документ задаёт локальный `id`; ссылка —
`pack_id:local_id`, например `base:goblin`. Категория определяется полем:
`art` ищет рисунок, `challenge` — испытание, `actions` — действия.
В одной категории одного пакета повторные ID запрещены, даже если имена файлов разные.
Разные категории могут использовать один local_id: арт и монстр `base:goblin`.

Проверяются существование ссылки, категория и доступность целевого пакета через
зависимости. Зависимости транзитивны; отсутствующие пакеты и циклы запрещены.
Контент в подпапках категории тоже загружается. Новые документы студия записывает
как `<id>.json`, рисунки — `<id>.art.json`. Версия формата сейчас `schema_version: 1`;
несовместимые версии не преобразуются молча.

## Единые шаблоны

`tiles/` содержит поверхности, `objects/` — мебель, двери, стационарные светильники
и переходы. Снаряжение, ловушки и точки интереса хранят рисунок в собственном
определении. Дополнительный тайл для них не создаётся. Размещения `objects` и
`doors` ссылаются на категорию `objects`.

[Полные результаты ревизии и совместимость](content-revision.md).

## Механические объекты

Пример монстра:

```json
{
  "schema_version": 1,
  "id": "scout",
  "name": "Разведчик",
  "symbol": "base:visual_monsters_goblin",
  "foreground": 10,
  "background": null,
  "art": "base:goblin",
  "stats": {
    "strength": 8, "dexterity": 14, "constitution": 10,
    "intelligence": 10, "wisdom": 8, "charisma": 8
  },
  "hit_points": 7, "armor_class": 13, "speed": 2, "initiative_bonus": 1,
  "actions": ["base:attack", "base:dodge"],
  "special_actions": [{
    "id": "dirty_strike", "name": "Подлый удар", "kind": "attack",
    "ability": "dexterity", "damage": "1d4",
    "effects": [{"kind": "condition", "condition": "poisoned", "duration": 2}]
  }]
}
```

HP и характеристики положительные, скорость и КД неотрицательные.
Инициатива — `d20 + мод. ЛОВ + initiative_bonus`. Большой арт не меняет
занимаемую клетку. Обычные действия — ссылки, особые — встроенные определения
с локальными ID. `inventory`, `spells`, `spell_slots`, `tags` необязательны.

Снаряжение: `weight`, `tags`, `durability`, `charges`, `slot`,
`weapon_damage`, `weapon_ability`, `properties`, `check_aids`.
`durability: null` означает неразрушаемый предмет, `charges: null` — без
ограничения применений. Сломанный/исчерпанный предмет не даёт свойств и тегов.
Броня `{"kind":"armor_class","amount":16}` заменяет КД; щит
`{"kind":"armor_bonus","amount":2}` прибавляет 2. Эти свойства работают
только у пригодного экипированного предмета.

```json
{"check_tag": "lockpicking", "mode": "advantage"}
```

В `check_aids` это даёт преимущество проверки с соответствующим тегом.
`automatic` даёт успех без броска и имеет приоритет над преимуществом.
Грузоподъёмность — сила × `carry_per_strength` класса, обычно 5 кг.
Перегрузка уже вычисляется, штраф движения пока не применяется.

`category` у снаряжения задаёт раздел инвентаря: `weapons` (вооружение),
`armor` (доспехи), `consumables` (расходники), `tools` (инструменты).
Поле доступно в форме студии. Если оно отсутствует или равно `null`, раздел
определяется по урону/тегам оружия, слоту и эффектам КД, затем зарядам/тегам
расходников; оставшиеся предметы относятся к инструментам. Старые пакеты
работают без миграции. Выброшенные предметы — экземпляры с координатами в
сохранении игры; исходная карта и её размещения не изменяются.

Заклинание: `level` 0–9, `target` self/other/any, `effects`.
Класс: `hit_points`, `starting_items`, `actions`, `spells`, `spell_slots`
(например `{"1":2}`), `carry_per_strength`, `order`.
Раса: `ability_bonuses`, `hp_per_level`, `speed`, `racial_spell` вместе с
положительным `racial_uses`. Предыстория: бонусы, стартовые предметы и теги,
`classes` (список ссылок на допустимые классы) и `skills` (названия навыков;
пока только отображаются). В TUI есть отдельный шаг выбора предыстории,
на котором показаны привязанные к классу варианты. С пустым `classes` старый
шаблон остаётся доступным через API/студию без ограничения класса; TUI использует
явную привязку. Движок отклоняет предысторию, привязанную к другому классу.

```json
{
  "schema_version": 1, "id": "thief", "name": "Вор",
  "classes": ["base:rogue"], "starting_items": ["base:crowbar", "base:rope"],
  "skills": ["Ловкость рук", "Скрытность"], "tags": ["thief"]
}
```

Действия: attack/dodge/stealth/magic/influence/special. Поля:
`ability`, `bonus`, `damage`, `effects`, `difficulty`.
Эффекты damage/heal/gold/experience суммируют `amount` и бросок `dice`;
condition задаёт `condition` и `duration`. Кубики имеют вид `1d6`, `2d4+2`,
до 100 кубиков и 2–1000 граней. Новые эффекты используют `params` и общий
Python-реестр: [пример регистрации](studio.md#добавление-зарегистрированного-эффекта).

## Арты

```json
{
  "schema_version": 1, "id": "torch", "name": "Факел",
  "width": 2, "height": 2,
  "layers": [{
    "id": "base", "name": "Основной", "visible": true, "locked": false,
    "cells": [
      [{"char":"*","foreground":208,"background":null}, null],
      [{"char":"|","foreground":130,"background":null}, null]
    ]
  }]
}
```

`null` — прозрачная клетка. `background: null` — прозрачный фон символа:
символ/его цвет заменяются, фон нижнего слоя сохраняется.
Слои композируются в порядке списка; скрытые не рисуются, блокировка относится
к редактированию. Размер каждой матрицы точно совпадает с холстом.
Один печатный символ занимает одну терминальную колонку; emoji, CJK,
комбинируемые последовательности и управляющие коды не проходят проверку.
TXT импортируется в один слой, строки дополняются пробелами до прямоугольника.
Экспорт TXT сохраняет видимые символы и теряет цвета/редактируемые слои.

## Тайлы

`TileDocument` задаёт `glyph`, `foreground`, `background`, `art`, начальные
`walkable` и `blocks_sight`. Поле `group` — произвольное название группы
(по умолчанию «Прочее»); `tags` — список латинских меток для поиска.
Библиотека и поиск тайлов карты учитывают название, ссылку, символ, группу и теги.
Теги не заменяют механические поля. Подпапки в `tiles/` не меняют ссылку на ID.
Необязательный `brush` связывает кисть с игровыми размещениями:

```json
{"trap":"base:terrain_fire","light":{"radius":6,"bright_radius":3}}
```

Поля: `trap` → ловушка, `interaction` → точка интереса, `item` → предмет,
`light` → стационарный свет, `transition` → переход на выбранную карту.
Кисти с ловушкой, взаимодействием, предметом или переходом должны быть проходимы.
Ссылки проверяются и учитываются при защите от удаления. Это инструкция
редактору: движок использует явные размещения карты и не выполняет кисть повторно.
Старые тайлы без `brush` работают с пустыми привязками. Новые карты со связанными
объектами не требуют миграции игрового состояния.
[Готовый каталог и правила начальных масок](tiles.md).

## Карты, ловушки и взаимодействия

`MapDocument` содержит `width`, `height`, три одинаковые по размеру матрицы:
`tiles` (ссылка на тайл или null), `walkability` и `blocks_sight` (bool).
`spawn` — `{x,y}`; координаты отсчитываются от нуля. `decorations` — размещения
артов; `traps`, `points_of_interest`, `monsters`, `equipment` — размещения шаблонов:

```json
{"id":"spikes_1", "ref":"base:spikes", "x":5, "y":3}
```

ID размещений уникальны на карте. Арт должен помещаться в карту; остальные
объекты размещаются на проходимых клетках. Старт не может совпасть с монстром,
два монстра не могут занимать одну клетку. Пересечение разных типов разрешено.
`transitions` задают `{id,x,y,target}` с ссылкой на карту; вход на клетку
переносит героя на её старт с сохранением ресурсов и часов.

Тайл задаёт glyph/цвета и начальные walkable/blocks_sight. Независимые маски
карты определяют движение; изменение рисунка не делает стену проходимой или наоборот.
`blocks_sight` перекрывает распространение света и взгляд героя; непрозрачная
целевая клетка видна, клетки за ней — нет. Проходимость остаётся независимой.
`ambient_light` принимает `dark`, `dim`, `bright` (для старых карт default `bright`).
`lights` — список стационарных источников `{id,x,y,radius,bright_radius,enabled}`;
источники можно ставить на стены. Радиус 1–32, яркий радиус 0–radius.
В тёмной области герой видит только соседние клетки по четырём направлениям.
Память посещённых клеток пока не хранится. `LightField.illumination` хранит
физическое освещение отдельно от `cells`, используемых при отрисовке. Условно
видимые клетки рядом с героем в темноте не становятся освещёнными. Осмотр
показывает физический свет и подсказку −5 к пассивным и активным проверкам
внимательности и анализа при тусклом свете. Подсказка не добавляет новые механики
навыков. Непрозрачная конечная клетка луча видна, даже если соседние клетки
принадлежат той же стене; клетки за стеной и проход сквозь закрытый угол скрыты.

Переносной источник — предмет со `slot: "hand"`, `hands: 1` и полем `light`:

```json
"light": {"radius": 8, "bright_radius": 4, "burn_minutes": 60, "fuel_tag": "lamp_oil"}
```

Без `fuel_tag` предмет получает топливо при создании и не заправляется (факел).
С тегом пустой источник требует предмет с этим тегом и положительным `charges`;
одно применение топлива заправляет его на `burn_minutes`.
`lit` и `fuel_minutes` принадлежат экземпляру и сохранению, не шаблону.
`consumed` вычисляется для одноразового источника без `fuel_tag` с нулевым топливом.
Он удаляется из инвентаря и размещений всех посещённых уровней, освобождая руку.
Старые сохранения со сгоревшими факелами очищаются при загрузке; лампы остаются.
Источник в руках светит при `equipped`; горящий предмет на земле светит в своём
размещении. Топливо сгорает за игровые минуты на всех посещённых уровнях.
Стационарные огни не расходуют топливо.
`hands` задаёт 0–2 руки; для старого контента слоты `weapon`, `main_hand`,
`off_hand`, `hand` занимают одну, тег `two_handed` — две. Одинаковые слоты
заменяют прежнюю экипировку, а универсальный слот `hand` занимает свободную руку.
Нехватка рук не снимает другие предметы автоматически.

Ловушка задаёт `hidden`, `ability`, `difficulty`, `success`, `failure`,
`repeatable`, `trigger: "enter"`. Срабатывание не расходует дополнительный ход.
POI задаёт `challenge` — ссылку на текстовое испытание. У испытания `text`,
`choices`, `repeatable`; вариант имеет id/text, ability/difficulty/check_tag,
required_tags/advantage_tags/automatic_tags, success/failure и minutes.
Недостающий обязательный инструмент запрещает выбор без затрат времени.
Состоявшийся выбор завершает одноразовое испытание, включая провал проверки.
`visible_tags` у варианта определяет его видимость: герой должен обладать всеми
перечисленными тегами. Например, `"visible_tags": ["sage"]` открывает выбор
мудрецу. Отсутствие тегов запрещает и прямой вызов команды. `required_tags`
сохраняет прежнее назначение — требования к выполнению видимого варианта.
TUI и браузер получают варианты через общий `available_choices(actor)`.

## Миграция и совместимость

`packs/base` создан неперезаписывающей миграцией текущего контента и фиксированной
карты. Исходники в `tuidungeon/content/data` и `tuidungeon/assets/art` сохранены.
`python -m tuidungeon.content.migrate` проверяет временный пакет до публикации
и отказывается перезаписывать существующий `base`.

`ContentCatalog.load(root)` и `--content-dir` читают прежний формат с короткими
ссылками; старые `docs/templates` оставлены для него. Для нового формата создавайте
объекты в студии, дублируйте файлы из `packs/base` или используйте шаблоны API.
`PackStore.runtime_catalog()` переводит проверенные документы в совместимые
доменные определения; короткие ключи base сохранены для старых Python-примеров.
Для новых клиентов используйте `SessionFactory` и полные ссылки пакетов.

## Локальные свойства размещений

Контракт `Placement.overrides` хранит отличия от шаблона, а
`challenge_overrides` — настройки испытания точки интереса. Объединение и
строгая проверка находятся в `content/placements.py`, создание экземпляров —
в `application/factories.py`. Общие определения не меняются; предметы и
монстры сохраняют настроенное определение при сохранении сессии.
[Формат и работа с инспектором](instance-properties.md).

Материалы: `flammable` обозначает горючесть, `wooden` — дерево / деревянные части.
Теги доступны предметам, тайлам и точкам взаимодействия. Правила разметки,
флажки студии и отличие от инструмента `поджог`: [материалы](materials.md).

Переносимые предметы имеют `size: "small" | "medium" | "large"`,
контейнеры — `storage.max_item_size` с теми же значениями. Размер независим
от веса; равные и меньшие размеры допускаются при соблюдении нагрузки.
Подробности, значения по умолчанию и примеры: [контейнеры](storage.md#размер-вещей-и-ограничения-контейнеров).
