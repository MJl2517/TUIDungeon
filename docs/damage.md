# Типы урона

Документ адаптирует предоставленный дизайн «TUI Dungeon — Типы урона» к текущему
движку. Это собственные упрощённые правила игры. Источник правил исполнения —
`tuidungeon/domain/damage.py`; JSON и формы студии задают параметры.

## Типы и группы

| Группа | Типы |
| --- | --- |
| `physical` — физический | `bludgeoning` — дробящий; `piercing` — колющий; `slashing` — рубящий |
| `elemental` — элементальный | `acid` — кислота; `cold` — холод; `fire` — огонь; `lightning` — электрический; `thunder` — громовой |
| `mystic` — мистический | `force` — силовой; `necrotic` — некротический; `psychic` — психический; `radiant` — лучистый |
| `toxic` — токсический | `poison` — ядовитый |

Всего 13 типов. Группы — сокращения для назначения защиты, а не дополнительные
типы урона. Например, сопротивление `physical` охватывает все три физических
типа. В поле `damage_type` группу указать нельзя.

## Расчёт

| Защита цели | Результат |
| --- | --- |
| Нет | 100% |
| Сопротивление | 50%, округление вниз: 5 → 2; 1 → 0 |
| Уязвимость | 200% |
| Иммунитет | 0 |
| Сопротивление и уязвимость одновременно | Отменяют друг друга до округления: 5 → 5 |

Иммунитет имеет приоритет. Одинаковая защита из нескольких источников не
складывается: сопротивление огню и элементальному урону вместе всё ещё дают
половину огненного урона. Проверки и броски кубиков выполняются до защиты.
Потеря HP ограничена оставшимся здоровьем.

Смешанный урон задаётся несколькими эффектами: например, рубящий и огненный
компоненты разрешаются отдельно. Каждый компонент округляется отдельно.
В результате сохраняются исходная величина, тип, величина после защиты,
применённая защита и фактическая потеря HP. Студия показывает эти значения
в журнале ловушек, событий и песочнице действий монстра.

Иммунитет к типу урона не означает иммунитета к отдельному состоянию:
нулевой ядовитый урон сам по себе не отменяет явно заданное `condition`.
Если событию нужна такая зависимость, её следует реализовать отдельной
механикой, а не проверкой имён или тегов внутри общего расчёта.

## Данные и студия

Эффект заклинания, предмета, ловушки, испытания или особого действия:

```json
{"kind": "damage", "dice": "2d6", "damage_type": "fire"}
```

Тип основного урона оружия:

```json
{"weapon_damage": "1d8", "damage_type": "slashing"}
```

Тип основного урона действия атаки монстра:

```json
{"id": "bite", "name": "Укус", "kind": "attack", "damage": "1d6", "damage_type": "piercing"}
```

Если действие использует экипированное оружие, тип и кубики берутся из оружия.
Безоружная атака остаётся `1d4` дробящего урона. Тип урона относится только
к основному компоненту; дополнительные `effects` задают собственные типы.
Поле типа недопустимо у лечения и остальных эффектов.

Защита задаётся в шаблонах монстров, рас, классов и снаряжения:

```json
{
  "damage_profile": {
    "resistances": ["piercing"],
    "vulnerabilities": ["bludgeoning"],
    "immunities": ["poison"]
  }
}
```

Это профиль базового скелета из дизайн-документа. Он принадлежит конкретному
шаблону: тег `undead` не добавляет всем существам иммунитет к яду или уязвимость
к лучистому урону. Гоблин не получает особой защиты по умолчанию.

Герой объединяет защиту расы и класса. Монстр получает защиту своего шаблона.
Защита снаряжения действует только пока вещь экипирована и исправна/пригодна
к использованию. Ношение защитного предмета в рюкзаке ничего не даёт.
В базовых расах, классах и броне новая защита автоматически не добавлена.

В студии появились русские поля **Тип урона** и **Защита от урона**:
сопротивления, уязвимости и иммунитеты выбираются из списков типов и групп.
У эффекта тип находится в форме механики **Урон**. Настройки размещения монстра
или предмета могут переопределять профиль, не изменяя общий шаблон.

## Окружение и поджог

Сохранены текущие правила дверей:

- Дерево получает урон и может быть явно подожжено; горение — 5 огненного урона
  за игровую минуту, материал по-прежнему определяет возможность горения.
- Стальная дверь принимает только кислоту, с удвоением урона.
- Прутья получают двойной кислотный урон; огонь их не повреждает.
- Каменная плита принимает дробящий урон. Кирка — отдельное свойство источника
  `pickaxe`, позволяющее повреждать плиту колющим уроном; это не 14-й тип.
- Адамантиевая дверь невосприимчива ко всем 13 типам. Действие «Дневной свет»
  сохраняет специальное превращение в каменную плиту.
- Кислота из флакона наносит `2d6`; существующая коррозия металла двери остаётся.
- Износ оружия при ударе по двери остаётся `1d4` независимо от нанесённого урона.

**Обычный огненный урон больше не включает горение двери автоматически.**
Действие «Поджечь» остаётся у исправных инструментов с тегом `поджог` / `ignite`.
Для горящего факела и оружия требуется экипировка. Огненное оружие без тега
поджога может наносить огненный урон без включения горения.

На уровне движка явно воспламеняющая атака вызывает
`damage_cell(position, amount, "fire", ignite=True, source_tags=...)`.
Без `ignite=True` огонь причиняет только урон. Поджог факелом или кремнем
использует отдельную команду `ignite_cell()` и восемь соседних клеток.
Для новой механики урона по окружению агент должен явно выбрать команду
поджога; общее имя типа не запускает состояние.

Масло — самостоятельная реакция окружения: первый огненный урон или явный
поджог расходует покрытие, добавляет 5 огненного урона и может зажечь деревянную
дверь. Иммунитет героя к огню отменяет его урон, но не сохраняет масло на клетке.
Объекты мебели пока не имеют собственного HP и состояния горения; один тег
`flammable` не создаёт для них скрытую модель разрушения.

## Совместимость и разметка

JSON остаётся авторским форматом; никаких новых файлов для каждого отдельного
броска или типа создавать не нужно. Во время игры используются неизменяемые
профили с заранее раскрытыми группами, без чтения JSON на каждом попадании.
Здоровье и собственная защита экземпляров сохраняются вместе с игровой сессией;
сохранения старого формата без профиля получают защиту из определений.

Старый `damage` без `damage_type` и вызов `take_damage(amount)` продолжают наносить
прежний прямой урон без проверки типов. Это режим совместимости, а не новый тип.
У оружия и атак без поля типа используется дробящий тип; автору нового оружия
следует выбирать его явно. Старые команды `physical` и `pickaxe` для дверей
поддерживаются на границе API, но не принимаются в поле типа JSON.
Прежний тег оружия `fire_damage` сохраняет старое сочетание огненного урона
и возможности поджога; для новых предметов используйте раздельные поля и теги.

Размечены известные виды оружия, стрелы/шипы, обвалы, падающая стена, кислота,
лава, огонь, яд, токсичные споры, отрицательная энергия и «Волшебная стрела».
У ядовитых поверхностей исправлен прежний ошибочный тег `acid` на `poison`.
Параметры урона и уже существующие состояния этих объектов сохранены.
Механические ловушки без описанного поражающего элемента и неопределённые
магические события остаются без типа до уточнения их механики автором.

Проверенная разметка воспроизводима и не перезаписывает уже заданные типы:

```bash
python -m scripts.prepare_damage_types          # показать изменения
python -m scripts.prepare_damage_types --write  # записать разметку base и старого каталога
python -m tuidungeon --validate-content
python -m unittest tests.test_damage
python -m scripts.check_damage_browser  # формы и журнал в настоящем браузере
```

## Следующие этапы

Тип сам по себе не накладывает состояние. Новые боевые состояния сейчас не
исполняются; существующие `condition` продолжают работать по прежним правилам.

| Тип | Направление расширения |
| --- | --- |
| Дробящий | Хрупкие конструкции и кости, разрушение объектов |
| Колющий | Точечные атаки, прокалывание мягких преград |
| Рубящий | Канаты, растения, паутина и ткань |
| Кислота | Временное снижение КД только у явно заданных типов существ, через отдельный эффект и реакцию шаблона |
| Холод | Замедление и сдвиг очереди JRPG-боя, замораживание воды |
| Огонь | Отдельное горение существ и объектов, зоны огня |
| Электрический | Шок и механизмы; мокрая цель не получает автоматического ×2 |
| Громовой | Шум, хрупкие объекты и будущие патрули |
| Силовой | Надёжный магический урон без обязательного состояния |
| Некротический | Отдельное ослабление лечения |
| Ядовитый | Отдельное отравление, без автоматических иммунитетов по общим тегам |
| Психический | Состояние смятения; иммунитеты задаются конкретным существам |
| Лучистый | Реакции конкретных существ и подавление регенерации, без общего ×2 по нежити |

Коррозия существ **не изнашивает броню** и **не снижает КД каждому, кто получил
кислотный урон**. В будущем конкретный шаблон разрешает реакцию, а отдельная
механика задаёт величину, длительность и правила повторного применения штрафа.
Конкретные значения и правила боевых состояний нужно определить при разработке
JRPG-режима. Для расширения используется общий реестр механик, а не новый
большой `if` по тегам монстров в обработчике урона.
