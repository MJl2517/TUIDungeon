# Игровые теги: правила взаимодействий

Единый словарь описывает **материал, природу источника, назначение, возможности и текущее состояние**. Он не содержит отдельных тегов для каждого меча, названия рецепта, уровня заклинания, веса или численного бонуса. Эти значения уже представлены игровыми полями.

- [Полный справочник с определениями каждого тега](gameplay-tag-reference.md).
- [Классификация всех предметов, поверхностей, объектов, атак, эффектов и способностей](content-tag-inventory.md).
- [Машиночитаемый каталог и разметка](gameplay-tags.json).
- Единый источник словаря: `tuidungeon/domain/tags.py`.

## Что хранить, а что вычислять

| Вид | Пример | Источник истины |
| --- | --- | --- |
| Постоянный авторский признак | `wooden`, `stone`, `holy`, `magic`, `flammable` | `tags` шаблона, с возможным переопределением экземпляра |
| Тип воздействия | `fire`, `poison`, `slashing` | Для урона — `damage_type`; в запросе превращается в признак, без второго поля урона |
| Возможность объекта | `movable`, `destructible`, `dismantlable`, `readable` | `movable`, `destruction`, `dismantle`, `reading`; не записывать производные флажки вручную |
| Содержимое | `liquid`, `water`, `holy`, `healing` | Текущие `liquid_kind`, `liquid_ml`, `liquid_effects`; пустой флакон не остаётся лечебным |
| Текущее состояние | `state_burning`, `state_broken`, `state_poisoned` | Состояние живого экземпляра; не ставить в шаблон |
| Количество / граница | вес, ёмкость, урон, КД, длительность, радиус | Числовое поле, не `heavy`, `damage_5`, `large_radius` и подобные теги |
| Допуск действия | подходящая станция, владение, дистанция, свет, обнаружение ловушки | Проверка команды; один тег не разрешает действие |

`storage` остаётся совместимым сокращением редактора: схема гарантирует `StorageSpec`. Сосуд жидкости имеет отдельную возможность `vessel`. Кувшин-декорация с контейнером вещей автоматически не превращается в сосуд воды.

## Независимые признаки

- **`wooden` и `flammable`**: дерево и горючесть независимы. Размеченный базовый деревянный контент горюч, но авторский огнеупорный предмет может иметь только `wooden`. Древко и металлический наконечник допускают одновременно `wooden` и `metal`.
- **`fire` и `ignite`**: огненное воздействие не всегда поджигает. `ignite` — явно предусмотренное назначение, а команда проверяет пригодность источника. Негорящий факел может иметь назначение `ignite`, но его `can_ignite` ложно.
- **`magic`, `holy`, `radiant` и `cursed`**: четыре разных понятия. Лучистый урон не доказывает освящение; священный символ не обязательно зачарован. Неизвестный, тёмный или легендарный артефакт не получает проклятие автоматически. `cursed` зарезервирован для явно заданного проклятия; в текущем каталоге таких предметов нет.
- **`poison`, `applies_poison` и `state_poisoned`**: источник яда, наложение состояния и отравленная цель. Ядовитые брызги наносят ядовитый урон, но не получают `applies_poison`, если в эффектах нет `condition: poisoned`. Отравленный герой не становится источником яда.
- **`organic`, `living`, `plants`, `fungi`, `food`, `edible`**: органика не обязательно живая или съедобная. Неизвестным грибам на карте не присваивается съедобность; съедобным ресурсным грибам присвоена явно.
- **`metal`, `glass`, `fragile`, `heat_safe`**: материал не гарантирует особое поведение. Хрупкость и допустимый нагрев текущих сосудов берутся только из `VesselSpec`; не добавляется автоматическая проводимость всех металлов.
- **`destructible`, `dismantlable`, `movable`**: разрушение, разбор на ресурсы и перемещение различаются. Стена не разбирается из-за тега `stone`. Дверь может выламываться, но не становится мебелью или обычной заготовкой разбора.
- **`repair` и `repairable`**: действие ремонта и потенциально ремонтируемая цель. Неповреждённая вещь может быть ремонтируемой по конструкции, но команда ремонта откажет.
- **`light_source`, `heat`, `state_glowing`, `state_burning`**: способность светить, доступное тепло и активные состояния. Зачарование «Свет» светит без горения. Потухший костёр не выдаёт `heat` в запросе экземпляра.

## Запросы из движка

```python
from tuidungeon.domain.tags import interaction_tags, liquid_tags

traits = interaction_tags(item)       # реальный экземпляр, включая состояние
tare = interaction_tags(item, include_contents=False)  # тара без содержимого
traits = interaction_tags(effect)     # конкретное свойство, без тегов остальных эффектов
traits = interaction_tags(spell)      # заклинание + его реально заданные эффекты
traits = interaction_tags(monster)    # тело и состояния, без материалов инвентаря
traits = interaction_tags(hero)       # расовые и врождённые признаки, без вещей в сумке
traits = interaction_tags(world_object)
traits = interaction_tags(door)       # живая Door, с открытием/замком/горением
traits = interaction_tags(raw, category="traps")  # JSON автора
contents = liquid_tags(item.liquid_kind) if item.liquid_ml else frozenset()
```

Материалы предмета сохраняются после поломки: сломанный деревянный посох всё ещё деревянный. Существующий `Equipment.tags` оставлен проверкой **доступных инструментальных разрешений** и может исключать сломанную вещь; для материала используйте `interaction_tags`.

Существующий `Character.tags` объединяет предысторию и рабочие предметы для проверок. Его нельзя использовать как материал тела: герой с посохом не деревянный и не горючий из-за этого посоха. Способности класса/расы перечисляются ссылками; знание огненного снаряда не приписывает огонь самому герою.

Запрос тары объединяет её физические свойства с текущим содержимым. Если реакция относится только к содержимому, проверяйте `liquid_tags` и отдельные `liquid_effects`. При нескольких материалах тег означает наличие значимых частей, а не процентный состав или однородный материал.

Не объединяйте все варианты испытания в свойства цели. В таблице эффекты каждого `choices[i].success/failure` перечислены отдельно; награда золотом не делает алтарь золотым. Для общего действия «Атака» конечный тип урона зависит от фактического оружия; запрос самого действия без выбранного оружия этого не угадывает.

## Правила для новых взаимодействий

| Сценарий | Признаки | Дополнительная проверка |
| --- | --- | --- |
| Поджечь цель | цель `flammable`, источник `ignite` | `can_ignite`, расстояние, видимость, поддержка горения этой цели |
| Рубить дерево / резать ткань | `wooden` / `cloth`, подходящий инструмент или `slashing` | Явная операция и параметры добычи; тег не создаёт ресурсы |
| Разобрать мебель | `furniture` и `dismantlable` | Рецепт разбора, инструмент, доступность объекта |
| Разбить хрупкую тару | `vessel`, `fragile` | Режим броска, траектория, отдельное применение жидкости |
| Тушить водой | содержимое `water`, цель `state_burning` | Вид воды, нужный объём, поддерживаемый небольшой огонь |
| Кипятить | сосуд `heat_safe`, содержимое `water`, станция `heat` | Конкретный вид воды и рецепт; не удалять автоматически соль/все яды |
| Очистить вещь | цель `state_contaminated`, подходящая вода | Объём и команда промывки |
| Переместить мебель | `movable` | Вес вместе с содержимым, занятость, дистанция, состояние |
| Ремонтировать | `repairable` и `state_damaged`/`state_broken` | Поддерживаемая цель, рецепт, материалы, свет, инструменты и владение |
| Святая реакция на нежить | источник `holy`, цель `undead` | Отдельное правило эффекта; `radiant`/иммунитеты не подменяются |
| Реакция на яд | `poison` либо `applies_poison` | Профиль защиты и отдельное наложение состояния |

Это рекомендации для последующего описания правил, а не автоматически добавленные механики. Система урона и защиты продолжает использовать [damage.md](damage.md), крафт — [crafting.md](crafting.md), слои мира — [world-layers.md](world-layers.md).

## Разметка текущего контента и границы уверенности

Проверены все базовые предметы, поверхности, объекты, точки взаимодействия, ловушки, монстры, общие/особые действия, заклинания, свойства, награды и источники рецептов. Расы, классы, предыстории и рецепты включены в отчёт, со ссылками на их реальные способности. Старая копия каталога синхронизирована через её собственный загрузчик.

Приняты явные авторские начальные материалы: верстак/алхимический стол — с деревянными частями; наковальня и котелок — железо; горн — камень; печь/кувшины/горшки/урны — керамика; бутылки/флаконы — стекло. Это данные стартового каталога, не универсальная догадка движка. Для наборов инструментов, неизвестных артефактов, самоцветов и неопределённого мусора состав не выдумывается.

Светлая/тёмная палитра, имя, ранг артефакта и школа заклинания не определяют святость, проклятие или материал. Священность размечена у явного святого символа и «Святыни», но не у всех алтарей. Книга заклинаний имеет `arcane` и `focus` только там, где они уже заданы; одна тема книги не делает бумагу магической.

`pending_effects` заклинаний остаются планируемыми возможностями: заморозка воды, блокировка реакций и прочие будущие реакции не помечаются действующими возможностями. Для заклинания «Дневной свет» в текущем документе нет исполняемого эффекта: отчёт фиксирует магическую природу, но не выдаёт автоматически новую механику освещения.

Старые технические теги (`transparent`, `opaque`, `walkable`, группы палитры, `decor_*`, конкретные сюжетные ключи и теги предысторий) сохранены и вынесены в отдельную колонку отчёта. Они не раздувают основной словарь. Геометрия берётся из `walkable`/`blocks_sight`, слои — из типа размещения; не пытайтесь открыть проход добавлением `transparent`.

## Редактор и обновление отчёта

В поле тегов студии есть поиск по русскому названию и ключу, выбранные признаки и сворачиваемый полный список по группам. Производные возможности и состояния редактируются через свои поля, а не через сотни флажков. Пользовательские теги по-прежнему можно добавлять обычным списком.

```bash
python -m scripts.tag_gameplay          # только проверить будущие дополнения
python -m scripts.tag_gameplay --write  # проверить, разметить base/legacy и обновить отчёты
python -m unittest tests.test_gameplay_tags -v
```

На Windows используйте `.venv\Scripts\python.exe`, на Linux — `.venv/bin/python`. Повторный запуск не добавляет дубликаты. Разметка не меняет пользовательские пакеты, карты, сохранения или размещения и сохраняет старые теги, кроме одной исправленной ошибки: у горячего источника `hot_spring` убран `fire` и явно заданы `water`/`liquid` (горячая вода не пламя). Автоматическое применение здесь — только проверенные правила стартового каталога; новые авторские шаблоны получают признаки явно.
