# Оптимизация движка

Реализован первый этап из [аудита](engine-audit.md): исправления контрактов,
подготовка контента, индексы размещений и кеширование отображения.
JSON остаётся авторским форматом. Во время ходов файлы карт не перечитываются.

## Исправления

- Предметы кисти отделены от изображения пола: после подбора не остаётся
  призрачный предмет. Старые размещения `tile_equipment_*` нормализуются при
  подготовке уровня, без изменения исходного файла. `brush.underlay` задаёт
  подложку явно; новая кисть также сохраняет существующий проходимый пол.
- Вложенные списки и словари шаблонов неизменяемы. Сессия закрепляет снимок
  контента; изменения студии применяются к новым сессиям.
- Компилятор преобразует только объявленные поля ссылок. Текст и параметры
  пользовательских механик больше не повреждаются удалением `base:`.
- Создание карты не наследует источники света вне новых размеров.
- Монстры, добавленные через движок, получают ссылку на определение и отображаются.

## Контракты для расширений

Поток данных: JSON → проверенные определения → `ContentSnapshot` → общий
каталог и `Terrain` → независимые экземпляры сессии → отображение.
`Terrain` хранит неизменяемые строки клеток и байтовые маски. Композиция графики
находится в `world/graphics.py`; прежний импорт `presentation/art.py` совместим.

Для изменения определения получите обычные данные через `model_dump`, измените
их и проверьте соответствующей моделью из `MODELS`. Авторское сохранение
выполняется через `PackStore.save` с ожидаемой версией файла. Не изменяйте
вложенные контейнеры загруженного документа или каталог действующей сессии.

Коллекции инвентаря и размещений отслеживают изменения. Используйте обычные
`append`, `pop`, замену элемента или среза. Перемещение монстра выполняется через
`GameState.move_monster`: метод возвращает новое размещение и обновляет индекс.
Не обходите эти операции вызовами базового `list` и изменением внутренних буферов.
Изменяемые HP, топливо, состояния и факты срабатывания принадлежат экземплярам.

Индексы ускоряют поиск существ, предметов, ловушек и соседних взаимодействий.
Обработка топлива выбирает предметы со световыми свойствами. Журнал интерфейса
ограничен последними 1000 событиями; он не заменяет формат сохранения или replay.

Освещение и кадры кешируются по геометрии, позиции наблюдателя, источникам света
и состоянию размещений. Физическое освещение переиспользуется при движении
наблюдателя. Для карт без преград обзору используется быстрый путь; для стен
сохранены существующие правила лучей. Новая механика, меняющая видимость,
должна обновлять учитываемое состояние и проверять инвалидацию кеша тестом.

TUI рисует область камеры и не пересчитывает карту на каждом пустом чтении
клавиатуры. Мигание курсора обновляется отдельно. Браузерная игра и её HTTP-снимки удалены; измеритель проверяет движок и отрисовку карты.

## Измерения

Исторические результаты ниже получены до удаления браузерного игрового клиента.
Текущий скрипт измеряет только движок и отрисовку, без HTTP-снимков.

Python 3.13.5, Linux, Intel Core i7-2600; синтетические открытые карты после
прогрева. До изменений — медиана 3 повторов, после — 5. Полное состояние
включает подготовку словарей, но не HTTP, браузер и JSON-кодирование.
После изменений здесь измеряется также команда движения, чтобы не сравнивать
старый расчёт с одним лишь чтением готового кеша.

| Сценарий | Полное состояние раньше | После хода теперь | Ход и кадр 80×24 |
| --- | ---: | ---: | ---: |
| 100×100, яркий свет | 437 мс | 18 мс | 5,4 мс |
| 256×256, яркий свет | 6998 мс | 117 мс | 20,3 мс |
| 100×100, 1000 предметов | 432 мс | 18,6 мс | 5,6 мс |
| 100×100, 100 источников света | 477 мс | 17 мс | 4,2 мс |

Последняя колонка измеряет движок и отрисовку области, а не полный ответ API.
Повторный полный запрос без изменений на 256×256 занимает 22 мс. За первый
snapshot выполняется один расчёт света вместо трёх. Ожидание среди 1000
предметов сократилось с 0,49 до 0,057 мс. Повторная загрузка 718 документов:
180 → 74 мс; доступ к подготовленному каталогу: 16 → 0,19 мс.

Цена глубокой неизменяемости — более дорогая проверка нового документа:
для 256×256 около 55 мс вместо 8 мс. Она выполняется при подготовке контента.
Полный JSON-ответ этой карты всё ещё около 3,6 МБ; камера уменьшает объём клеток.
Эти цифры не гарантируют FPS: стеновые карты, AI и транспорт нужно измерять отдельно.

Сырые результаты: [до](benchmarks/engine-baseline.json),
[после](benchmarks/engine-optimized.json). Воспроизведение без записи карт:

```bash
.venv/bin/python -m scripts.benchmark_engine --sizes 32 100 256 --repeat 5
.venv/bin/python -m scripts.probe_engine_contracts
```

## Следующие этапы

Единый контракт команд, версии контента в сохранениях и изменяемые дельты
геометрии остаются дальнейшей работой. Для очень больших миров можно добавить
чанки и палитру числовых ID; SQLite нужен при требованиях к запросам и транзакциям,
а не только из-за числа объектов карты. Заменять JSON сейчас не требуется.
Алгоритм видимости за стенами, планировщик активных источников и копирование
холста/history редактора стоит оптимизировать по отдельным профилям.
