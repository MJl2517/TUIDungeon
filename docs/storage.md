# Контейнеры

Тег `storage` добавляет контейнер существующему объекту окружения или точке
интереса. Отдельный тайл-копия не нужен. Размечены 18 шаблонов: сундуки, ящики,
мешки, урны, бочки, горшки, кувшины, большие сосуды и шкафы. Спальный мешок и
ключ от сундука контейнерами не считаются.

В студии откройте шаблон или выберите размещение инструментом **V**. В поле
«Контейнер» задайте вместимость, личный режим и начальное содержимое: ссылки
на предметы и количество. Ссылки и общий вес проверяются до сохранения.
По умолчанию вместимость 1000 кг, контейнер пустой и лутовый.

```json
{
  "tags": ["storage", "wooden", "flammable"],
  "storage": {
    "capacity": 1000,
    "personal": true,
    "contents": [
      {"item": "base:rations", "quantity": 3},
      {"item": "base:oil", "quantity": 2}
    ]
  }
}
```

Один тег без настроек использует значения по умолчанию. Настройки `storage`
автоматически добавляют тег. Чтобы отключить контейнер, уберите тег и задайте
`storage: null`. Локальные `overrides.storage` на карте меняют свойства только
одного размещения.

## Обмен

Подойдите на соседнюю клетку по четырём направлениям или встаньте на клетку
контейнера и нажмите Enter. Объект должен быть видим. Если рядом несколько
взаимодействий, сначала выберите объект. В браузерном тесте нажмите «Открыть
контейнер».

Окно в стиле Midnight Commander показывает инвентарь слева и содержимое справа.

| Клавиша | Действие |
| --- | --- |
| Tab, ←/→ | Переключить колонку |
| ↑/↓ | Выбрать предмет |
| PgUp/PgDn, Home/End | Перейти по списку |
| Enter, F5 | Перенести предмет |
| ←/→ при выборе количества | Изменить количество |
| Home/End при выборе количества | Один / вся группа |
| Backspace, Esc | Отменить количество, затем закрыть окно |
| F4 в игре | Связанное текстовое событие, если оно есть |

Выбор вещей и ползунок поддерживают мышь. Один экземпляр переносится сразу;
для группы появляется ползунок, по умолчанию выбран один предмет. Группировка
учитывает прочность, заряды, топливо и индивидуальный внешний вид. Каждая вещь
сохраняет ID и ресурсы: группа не заменяет игровые экземпляры.

Перенос проверяет нагрузку получателя: у героя обычный максимум, у контейнера
вместимость. Неудачная операция ничего не меняет. Положенная вещь снимается с
экипировки и гасится; оставшееся топливо сохраняется. Меню и обмен не расходуют
ходы. Движение при открытом окне отключено.

## Личный и лутовый режимы

- **Личный**: можно класть и забирать. `replace_loot()` запрещает обновление
  такого контейнера.
- **Лутовый**: можно только забирать. Ограничение проверяется движком, включая
  прямые команды API. Будущий генератор сможет обновлять только такой лут.

Автоматического обновления по таймеру пока нет. Начальное содержимое создаётся
один раз при первом посещении уровня. Повторный переход сохраняет состояние;
сохранение игры хранит и пустые контейнеры, их вместимость и личный режим.
Перезапуск теста создаёт чистую сессию из авторских данных. Игровой обмен не
перезаписывает исходные JSON.

Старые текстовые события сохранены: F4 в игре, отдельные варианты в браузере.
Их проверки пока не запирают окно содержимого.

## Проверка и расширение

Для проверки всех контейнеров откройте [полный полигон](../packs/dev/containers.md):
18 шаблонов, каждый в лутовом и личном варианте, с предметами внутри.
Между образцами пять пустых клеток, над каждым указан номер.

```bash
./run.sh --test-map dev:all_containers
# Windows:
.\run.bat --test-map dev:all_containers
# Обновить полигон после добавления новых шаблонов storage:
python -m scripts.build_developer_containers --force
```

Небольшая карта для отдельных проверок:

```bash
./run.sh --test-map dev:storage_lab
./run.sh --terminal --test-map dev:storage_lab
python -m scripts.prepare_storage         # проверить разметку без записи
python -m scripts.prepare_storage --write # добавить недостающий storage в base
python -m scripts.check_storage_browser
```

На Windows используйте `run.bat` и Python окружения проекта. Исходный полигон
содержит личный сундук с пайками и маслом, лутовый мешок с зельями и факелами
и личный шкаф. Рабочую карту можно редактировать в студии; автоматические
проверки используют фиксированную копию из `tests/fixtures/storage_lab.json`.
Базовые шаблоны пустые: начальный лут задаёт автор, случайная генерация остаётся
следующим этапом.

Контракты: `content/schemas.py` — данные; `world/storage.py` — экземпляр;
`domain/storage.py` — группы; `application/storage.py` — перенос;
`presentation/storage.py` — окно игры; `StorageDialog.tsx` — окно браузера.
