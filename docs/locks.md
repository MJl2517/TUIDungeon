# Общие замки и их индикаторы

Замок имеет два независимых свойства:

| Качество (`lock_quality`) | Цвет | СЛ взлома |
| --- | --- | --- |
| `cheap` — лёгкий | Бронзовый (130) | 10 |
| `normal` — средний | Синевато-железный (110) | 15 |
| `expensive` — сложный | Золотой (220) | 20 |
| `legendary` — легендарный | Фиолетовый (135) | 25 |

Цифры цветов — индексы 256-цветной палитры. Механизм (`lock_complexity`)
определяет **рисунок и время**, а не СЛ: `simple` — один ход,
`complex` — десять ходов. Например, лёгкий замок может иметь сложный механизм.

## Отображение рядом с героем

Если запертый объект находится не дальше одной клетки (включая диагонали),
его изображение временно заменяется общим изображением замка. После отхода,
успешного взлома или применения ключа возвращается обычный рисунок объекта.
Отдельные запертые варианты каждого сундука и двери для игры не требуются.
Старые `state_symbols.locked` читаются, но игра использует закрытый рисунок
вдали от героя и общий индикатор вблизи.

Индикатор не показывается сквозь преграды, в полной физической темноте,
поверх героя или живого существа. Тусклый свет не меняет обозначение качества
на серое: это служебная подсказка, а не источник света. Маски, HP, координаты,
время и коллизии не меняются. У горящей двери цвет качества сохраняется,
а фон индикатора мигает цветом горения.

В оконном режиме «Символы» используются общие изображения 16×16;
в текстовом режиме и терминале `l` означает простой, `L` — сложный механизм.
Оба режима используют одинаковые состояния и цвета.

## Два служебных тайла

В `base` добавлены временные рисунки и тайлы:

- `base:service_lock_simple` — простой механизм;
- `base:service_lock_complex` — сложный механизм.

У каждого есть одноимённая запись библиотеки символов. Рисунок можно заменить
через обычное назначение символа или пиксельный редактор. Цвет в определении
служебного тайла не определяет качество: его задаёт экземпляр замка.

В пакете `tiles` назначены рисунки атласа: №491 для простого
(`tiles:cell_0491`), №540 для сложного (`tiles:cell_0540`). Они заменяют
временную графику `base` по общему правилу приоритета пакетов.

Служебный тег **`lock_indicator`** работает вместе ровно с одним тегом
**`lock_simple`** или **`lock_complex`**. Тайлы находятся в категории `service`,
не блокируют движение/обзор и не имеют механик кисти. Они служат источником
графики, а не отдельными размещениями замков на карте.

Чтобы добавить собственный рисунок через пакет `tiles`, создайте в нём
служебный тайл с соответствующей парой тегов и назначьте символ своей библиотеки:

```json
{
  "schema_version": 1,
  "id": "my_simple_lock",
  "name": "Простой замок",
  "symbol": "tiles:my_lock_picture",
  "glyph": "l",
  "map_category": "service",
  "group": "Служебные: замки",
  "tags": ["lock_indicator", "lock_simple"],
  "walkable": true,
  "blocks_sight": false
}
```

В одном пакете разрешён один активный тайл на механизм. Приоритет:
собственный тайл пакета текущей карты; затем единственный пользовательский
вариант среди подключённых пакетов; затем `base`. Если пользовательских
вариантов несколько и карта не выбирает свой пакет, используется `base`.
Без служебных тайлов внешний пакет получает текстовые обозначения `l`/`L`.
Индекс графики собирается один раз для снимка контента, а замки ищутся только
в соседних клетках. Не требуется сканировать всю карту при каждом кадре.

## Двери и контейнеры

У дверей прежние поля находятся в `brush.door`: `locked`, `lock_quality`,
`lock_complexity`. Добавлено необязательное `key_tag`. Выламывание и
разрушение по-прежнему определяются материалом двери; это не свойства качества
замка. Space открывает/закрывает уже отпертые двери и не вскрывает замок.

У контейнера добавьте `storage.lock` в шаблоне или свойствах экземпляра карты:

```json
{
  "storage": {
    "capacity": 300,
    "max_item_size": "medium",
    "personal": true,
    "lock": {
      "locked": true,
      "lock_quality": "normal",
      "lock_complexity": "complex",
      "key_tag": "chest_key"
    },
    "contents": [{"item": "base:spellbook", "quantity": 1}]
  }
}
```

`lock: null` означает отсутствие замка. Наличие замка не зависит от личного
режима, вместимости и допустимого размера вещей. Пока он заперт, открыть
инвентарь контейнера, взять или положить вещи нельзя. Осмотр не раскрывает
количество и вес содержимого. Взаимодействие по Enter предлагает вскрыть
замок или применить подходящий ключ. Ключ не расходуется.

Взлом использует ту же проверку, что двери: d20 + модификатор Ловкости против
СЛ качества, без преимущества от воровских инструментов. Нужны исправные
воровские инструменты. У сложного механизма Space тратит по ходу и заполняет
общую шкалу из десяти клеток. Воровские инструменты имеют 10 прочности:
финальный провал расходует 1, успех и отмена не расходуют прочность.
На нуле инструмент сломан; для следующей попытки нужен исправный набор.
Текущая прочность показывается в инвентаре и подсказках взлома. У сложного
механизма промежуточные нажатия Space не изнашивают инструмент.
Backspace отменяет попытку без возврата времени.
Потеря инструмента, недоступность/уничтожение объекта или потеря сознания
прерывают работу. Применение ключа занимает один ход.

Состояния заперто/отперто и незавершённый взлом сохраняются. Поднятый сундук
сохраняет замок и содержимое при переносе, сохранении и установке обратно.
Старые сохранения без состояния замков контейнеров сохраняют прежний свободный
доступ; старые попытки взлома считаются попытками взлома двери.
Старые воровские инструменты без прочности получают полную прочность при
загрузке; сохранённый износ и поломка теперь сохраняются без восстановления.

Шаблон `base:chest` переведён с текстового испытания на общий замок:
среднее качество, простой механизм, ключ с тегом `chest_key`.
Обычные `base:terrain_chest*` остаются без замков по умолчанию: добавьте
замок нужному размещению в студии. Старое испытание `base:locked_chest`
сохранено как отдельный сценарий для совместимости внешних ссылок;
произвольные текстовые испытания не распознаются как замки по названию.

Проверки: `tests/test_locks.py`, тесты дверей, хранения, света и сохранений.
