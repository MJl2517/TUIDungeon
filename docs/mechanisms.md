# Рычаги, нажимные плиты и связанные объекты

Механизмы работают в общем Python-движке оконного и терминального клиентов.
Игровое состояние сохраняется в сохранении; файлы пакета не изменяются.

## Проверка в игре

В студии откройте карту **`tiles:mechanisms_lab`** («Механизмы: рычаги и плиты»)
и запустите её в игровом окне, например классом `dev:empty_tester`.
Координаты ниже отсчитываются с нуля.

| Объект | Клетка | Проверка |
|---|---|---|
| Рычаг | 3, 3 | Enter → рычаг → включить/выключить; действие занимает один ход |
| Нажимная плита | 3, 7 | Сигнал включён только пока герой стоит на плите; ожидание его сохраняет |
| Металлическая дверь | 7, 3 | Открывается при включении, закрывается при выключении |
| Ловушка | 10, 3 | Включение взводит; проверка и урон происходят только при входе |
| Магический огонь | 13, 3 | Загорается и освещает окружение, гаснет без сигнала |
| Иллюзорная стена | 17, 3 | Исчезает, открывая пол, движение, свет и обзор; после выключения возвращается |
| Дополнительный свет | 20, 7 | Управляется кодом `demo`, яркий радиус 2, тусклый 4 |

Оба источника соединены с целями. Достаточно одного включённого источника:
сход с плиты не выключает рычаг. Выключите рычаг для отдельной проверки плиты.
Сохраните игру с включённым рычагом или нажатой плитой, загрузите и продолжите.
После перехода на другую карту герой больше не давит на прежнюю плиту.

## Настройка в студии

1. Поставьте **«Переключаемый рычаг»** или **«Нажимную плиту»** из группы
   «Механизмы» в разделе «Особое». Для стены-иллюзии используйте отдельный
   объект **«Иллюзорная стена»** поверх свободного пола, без маски стены.
2. Инструментом **«Выбрать»** нажмите на источник. В инспекторе откройте
   **«Связать на карте»** и нажимайте на двери, ловушки, магические огни,
   иллюзии или служебные источники света. Связанные клетки подсвечены зелёным.
   Повторный клик убирает прямую связь; если на клетке несколько целей,
   выберите нужную кнопкой в панели связей. **Esc** завершает связывание.
3. Альтернатива: задайте **«Код механизма»** у источника и такой же
   **«Код активации»** у целей. Допустимы строчные латинские буквы, цифры и `_`,
   первая буква обязательна, например `crypt_gate`. Код действует только внутри
   текущей карты. Прямые связи и связи по коду объединяются.
4. Сохраните карту и запустите тест. Настройки относятся к размещению,
   исходный шаблон остаётся прежним.

Прямую связь можно удалить крестиком в списке. Если цель остаётся связана по коду,
измените или очистите код: снятие прямой связи не отключает канал.
При удалении цели студия очищает ссылки на неё. При копировании области прямые
ссылки на скопированные цели переназначаются копиям; внешние ссылки сохраняются.
Коды при копировании сохраняются: для независимой копии цепочки измените её код.

## Контент и ограничения

У объекта-источника:

```json
{
  "mechanism": {
    "trigger": "lever",
    "initially_on": false,
    "code": "crypt_gate"
  },
  "mechanism_targets": ["gate", "trap", "fire", "illusion"],
  "state_symbols": {"off": "tiles:cell_0495", "on": "tiles:cell_0494"}
}
```

Для плиты `trigger` равен `pressure_plate`; графика `off` — `tiles:cell_0493`,
`on` — `tiles:cell_0492`. `initially_on` используется только рычагом.
Источники неподвижны; плиту делают проходимой и прозрачной для света.
У объекта-иллюзии `illusion: true`. У размещения цели или служебного света
код записывается как `activation_code`, рядом с `id`, `x`, `y`, `ref`.
Отдельный код не нужен при прямом выборе целей.

Механизмы не обходят уникальные ключи, не управляют дверями-переходами и
неподвижными каменными плитами. Подпорка мешает приводить дверь в движение.
Если закрываемая клетка занята героем, существом, NPC или предметом, закрытие
отложено до освобождения клетки. Разрушенную дверь сигнал не восстанавливает.

Включение ловушки не сбрасывает её однократное срабатывание и не запускает
дистанционную атаку. Запас топлива переносных факелов и ламп сигналом не меняется:
связывать следует магические огни или служебный свет, а не подставки с предметами.

Старые рычаги, у которых заданы только `mechanism_targets`, продолжают один раз
открывать двери. Режим связывания студии добавляет им переключаемый механизм.
Старые сохранения получают пустые состояния сигналов.

Проверки: `python -m unittest tests.test_mechanisms tests.test_tiles_doors`;
браузерный сценарий студии — `python scripts/check_workspace_browser.py`.
