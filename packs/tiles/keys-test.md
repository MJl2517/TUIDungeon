# Ключи: добавленные тайлы и проверка

| Ячейка | Предмет | Назначение |
| --- | --- | --- |
| 572 | `tiles:key_container` | Обычные замки контейнеров на родном уровне; коричневый |
| 573 | `tiles:key_door` | Обычные замки дверей на родном уровне; золотистый |
| 574 | `tiles:key_unique` | Только замки с совпадающим кодом в любых локациях; фиолетовый |

Ключи не расходуются, не требуют экипировки или владений. Они находятся в группе
снаряжения. Названия и описания явно различают двери и контейнеры. У обычного ключа
осмотр показывает название родного уровня. Привязка задаётся уровнем первоначального
размещения, а не последнего подбора: перенос, контейнер, мебель и сохранение её не меняют.
Ключи разных уровней не объединяются в одну стопку; уникальные с разными кодами — тоже.

Подойдите к замку → взаимодействие → **Открыть подходящим ключом**. Подходящий ключ
выбирается из инвентаря автоматически. В меню самого ключа **Выбрать замок рядом**
открывает обычные взаимодействия. Успешное отпирание занимает один ход, неподходящий
ключ не расходует время. После отпирания дверь/контейнер открываются обычным действием.

Уникальный код имеет приоритет: ключи уровня и старые ключи по тегу его не обходят.
Взлом и разрушение остаются отдельными существующими механиками; уникальность кода
сама по себе не делает замок неразрушимым. Старый `key_tag` продолжает работать у
обычных замков для совместимости пакетов.

## Настройка в студии

1. Поставьте дверь или контейнер и выберите **Выделение (V)**. Настраивайте конкретный
   экземпляр, чтобы не менять остальные объекты того же шаблона.
2. У двери найдите **Код уникального замка / ключа**. У контейнера раскройте хранилище
   и настройки замка (создайте замок, если его нет). Включите **Уникальный замок**:
   студия создаст восьмизначный буквенно-цифровой код. Поле выделяется при фокусе,
   его можно скопировать через Ctrl+C. Само состояние **Заперт** задаётся отдельно.
3. Разместите `tiles:key_unique` на нужной карте. Выберите его через V и вставьте код
   в **Код уникального замка / ключа**. Можно изменить имя экземпляра, например
   «Ключ от северной башни». Для ключа внутри контейнера выберите этот предмет в
   начальном содержимом и заполните код у соответствующей записи.
4. Сохраните обе карты, если ключ и замок находятся в разных локациях. Перезапустите
   тест после изменения исходной карты. Существующее сохранение не переписывает пакеты.

Пустой код замка означает обычный замок. Пустой код уникального ключа означает, что
он пока не связан ни с одним замком. Регистр не важен: коды сохраняются в верхнем.
Допускаются 4–16 латинских букв/цифр. Один и тот же код можно намеренно назначить
нескольким замкам — тогда уникальный ключ открывает их все, включая двери и контейнеры.

JSON для размещённой двери: `overrides.brush.door.key_code = "AB12CD34"`.
Для контейнера: `overrides.storage.lock.key_code`. Для лежащего ключа:
`overrides.key_code`. Для ключа в содержимом: `{"item":"tiles:key_unique",
"quantity":1,"key_code":"AB12CD34"}`. Код нельзя назначить обычному ключу уровня.

## Полигон

Откройте в студии `tiles:keys_lab` и запустите игру либо выполните:

```powershell
.\run.bat --test-map tiles:keys_lab --test-class dev:empty_tester --seed 42
```

На Linux: `./run.sh --test-map tiles:keys_lab --test-class dev:empty_tester --seed 42`.
Можно добавить `--terminal`. Второй связанный уровень — `tiles:keys_annex`.

Координаты ниже соответствуют координатам карты студии с нуля:

| Место | Проверка |
| --- | --- |
| (2,3), (3,3), (4,3) | Три ключа на земле; уникальный настроен на `KEYS2026` |
| (6,3) | Обычная запертая дверь: работает только ключ 573 своего уровня |
| (9,3) | Обычный запертый шкаф: работает только ключ 572 своего уровня |
| (6,6), (9,6) | Уникальные дверь и шкаф: только ключ с кодом `KEYS2026` |
| (3,6) | Личный шкаф с дополнительными ключами, в том числе уникальным с кодом |
| (13,8) | Фиолетовый портал между двумя тестовыми уровнями |

На втором уровне старые обычные ключи не подходят, местные подходят. Уникальный
ключ первого уровня открывает связанные замки второго. Сохраните игру на втором
уровне, загрузите и вернитесь: привязки и открытые замки сохраняются.

Проверки: `python -m unittest tests.test_keys`. Проверяются тип/уровень/код,
переходы, выбрасывание, контейнеры, перенос мебели, стопки, сохранения и старые
предметы без новых полей. Генерация кода и назначение ключу также проверены в браузере.
