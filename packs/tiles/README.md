Пакет для согласованного создания тайлов и предметов. Зависимость `base`
позволяет ссылаться на существующие механики и материалы. Существующие пакеты
и назначения графики не заменяются.

Откройте `tileset-viewer.bat` в корне проекта. На Linux/macOS:
`./tileset-viewer.sh` (или `python3 tools/tileset-viewer/server.py`). Откроется браузер с отдельным локальным
просмотрщиком; студия не требуется. Закрытие консоли останавливает просмотрщик.
Прямое открытие `tools/tileset-viewer/index.html` позволяет выбирать ячейки,
но для записи отметок нужен запуск указанной командой.

## Отметки добавленных тайлов

Зелёные галочки **определяются автоматически** по реальным назначениям символов
объектам, поверхностям, предметам и другим игровым определениям в `packs/tiles`.
Учитываются основной рисунок, варианты и рисунки состояний. Сам по себе импорт
картинки в библиотеку, размещение на карте или архивное задание не дают отметку.
При удалении последнего назначения галочка исчезает. Пакет `base` содержит весь
исходный лист: это библиотека, а не подтверждение реализации всех его ячеек.

Сверка выполняется при открытии и каждые 5 секунд. Кнопка **Сверить с пакетом**
обновляет её немедленно. При наведении видны имена и ID игровых определений,
использующих ячейку. Флажок выбранных ячеек показывает итог сверки и не редактируется
вручную; при смешанном выделении он показывает смешанное состояние.

`tools/tileset-viewer/progress.json` — автоматически обновляемый снимок для Git.
Включайте его в коммит вместе с тайлами. После обновления репозитория на другом
компьютере просмотрщик заново проверяет фактический контент. Для сверки без браузера:
`tileset-viewer.bat --sync-progress` или `./tileset-viewer.sh --sync-progress`.
Завершение задания через CLI также обновляет снимок, но галочка не подтверждает
выполнение всех механик промпта: очередь и архив по-прежнему ведутся отдельно.

Номер берётся из `symbols.source.coordinates` `[столбец, строка]` с нуля.
`source.location` определяет лист: `assets/1 bit/` — монохромный,
путь к `colored-…` — цветной, `assets/1_bit_input/` — кнопки. Поворот, отражение
и окраска символа не меняют номер исходной ячейки. При ошибке контента показывается
«Статус не проверен»; последний сохранённый снимок не перезаписывается.

Номера ячеек идут с 1 слева направо, затем следующая строка. Координаты —
`[строка, столбец]`, с 1. Shift + щелчки выбирают несколько ячеек;
Shift + протягивание выделяет клетки вдоль движения мыши. Скопированный список
содержит название листа, номера и координаты. Масштаб не меняет номера.

Пример задания: «Лист Kenney 1-Bit монохромный, ячейки 101, 102, 103:
деревянные стены, коричневые, непроходимые, не пропускают свет, горючие».
Для диапазонов указывайте строку и столбцы явно: «строка 3, столбцы 6–12
включительно». Это исключает путаницу между диапазоном номеров и прямоугольником.

По каждому заданию создаём определения в этом пакете и соответствующие символы
16×16 из выбранных ячеек. Цвет и игровые теги задаются определениями, рисунок —
символом. Копирование существующей механики не требует изменения её оригинала.
Первая партия реализована: [проверка растительности](vegetation-test.md).
Ключи 572–574 и уникальные замки: [настройка и тестовый маршрут](keys-test.md).

Рисунки и назначения хранятся в `packs/tiles/symbols` и определениях объектов,
исходные листы — в `assets`. Игровой атлас собирается из символов в фиксированном
порядке. После клонирования всего репозитория на Windows или Linux переносить
кеш атласа не нужно. Для графического режима выберите в игре оформление
**Символы**; эта настройка каждого компьютера хранится отдельно от контента.

## Очередь новых заданий и архив

Выделите 5–20 тайлов, заполните **Что нужно реализовать**, нажмите
**Добавить задание**, затем **Сохранить задания в файл**.
Каждое задание получает постоянный ID. Новые задания можно править и удалять.
При редактировании восстанавливаются лист и выделение.

`tools/tileset-viewer/tasks.json` хранит очередь и архив со статусами, датами
и примечаниями. `tools/tileset-viewer/tile-requests.md` собирается автоматически
**только из незавершённых заданий**. При просьбе «обновить тайлы» агент читает
этот MD: готовые промпты повторно обрабатывать не требуется. Оба файла добавляйте
в Git. MD можно восстановить из JSON; вручную правьте задания в просмотрщике.

После реализации и проверки нажмите **Выполнено**. Задание исчезнет из рабочего
MD и вкладки **Новые**, но сохранится во вкладке **Архив** с исходным текстом.
Текст архивных заданий свёрнут. **Создать доработку** копирует исходный запрос
в новый черновик с отдельным ID: например, можно поменять механику уже готовой
стены, не переписывая историю. Зелёные галочки атласа и статусы заданий независимы;
галочка сама по себе не подтверждает выполнение всего промпта.

Агент может завершить проверенные задания без браузера. Под каждым новым
заданием в MD есть готовая команда с ID и версией текста:

```bash
./tileset-viewer.sh --list-pending
./tileset-viewer.sh --complete task_ID@ВЕРСИЯ --note "Что реализовано и проверено"
```

Можно передать несколько `ID@ВЕРСИЯ` после `--complete`. Если формулировка
успела измениться, завершение отклоняется: сначала нужно прочитать новую версию.
Список `--list-pending` выводит только ID, номера тайлов и версии, без архива
и длинных промптов. На Windows используйте `.\tileset-viewer.bat`.

Если другая вкладка или агент изменили очередь, устаревшее сохранение
отклоняется и не возвращает архивные запросы в работу. Черновик остаётся в
открытой вкладке; перед **Обновить список** его можно сохранить кнопкой
**Скачать черновик**. Без несохранённых правок список обновляется автоматически.
Изменения из интерфейса и CLI защищены общей файловой блокировкой.

При переходе на очередь первые 12 заданий (24 изображения растительности)
перенесены в архив по уже реализованному контенту и проверкам. Исходные файлы
до переноса сохранены локально в `backups/tileset-tasks-20261013_094018/`.
Сами механики, символы и отметки атласа этим переносом не изменены.
